# 목일중 골든벨 — 70명 전체 실시간 동기화 버전

2026-11-23 업로드된 원본 HTML을 기반으로 한 **시험 운영용 완성 코드**입니다. `index.html`은 기존 3D 운동장, 캐릭터, 휴대폰 조이스틱, 바닥 클릭 이동, O/X 및 4지선다 자동 이동, CSV 문제은행, 교사 메뉴, 효과음 등을 유지합니다. `server.py`는 Firebase 대신 경량 WebSocket 게임 서버를 제공합니다.

## 핵심 사양

| 구분 | 내용 |
|---|---|
| 방당 정원 | 학생 최대 **70명** + 교사 1명 |
| 학생 화면 | 다른 **69명까지 포함한 모든 학생 캐릭터·이름·색·동작·생존 상태** 표시 |
| 위치 동기화 | 클라이언트 최대 4Hz 업로드, 서버 250ms 간격으로 **변경분 하나로 묶어** 모두에게 전달 |
| 서버 권한 | 교사 인증, 문제 출제, 타이머, 시각 마감, O/X·4지선다 구역 확정, 결과 판정 |
| 재접속 | 브라우저의 임시 세션 키로 자동 재연결; 일시 끊김 35초간 자리 유지 |
| 지속 저장 | 없음. 서버 프로세스 종료·재시작 시 게임 방과 진행 상태는 사라짐 |
| 실행 서버 | Python 3.10+ 및 aiohttp 3.9+; 단일 프로세스·단일 서버 |

**주요 변경:** Firebase RTDB `onChildChanged` 전체 구독 대신 WebSocket delta-batching. 모든 학생은 **전체 학생 정보를 받습니다**. '주변 15명만 표시' 또는 '교사만 전체 표시' 방식이 아닙니다.

## 빠른 시작 (Ubuntu / Windows 공통)

```bash
python -m venv .venv
# Ubuntu / Linux
source .venv/bin/activate
# Windows PowerShell은 .venv\Scripts\Activate.ps1
python -m pip install -r requirements.txt

# Ubuntu / Linux에서만 실행하는 예시
TEACHER_PASSWORD='여기에_8자_이상의_관리자_비밀번호' python server.py
```

실행 후 서버 컴퓨터 브라우저에서 `http://127.0.0.1:8080`에 접속합니다. 먼저 교사로 로그인하여 방 코드를 만들고, 학생에게 **동일한 서버 주소와 방 코드**를 알려줍니다.

### 학교 LAN을 통해 접속

학교 정보보안 담당자의 허가를 얻은 후 서버에 다음처럼 바인딩할 수 있습니다.

```bash
HOST=0.0.0.0 PORT=8080 TEACHER_PASSWORD='여기에_8자_이상의_관리자_비밀번호' python server.py
```

교사도 서버의 실제 IP(예: `http://192.168.x.y:8080`)로 접속해야 QR 코드가 학생들에게 올바른 URL을 제공합니다. 교사 PC와 학생용 Wi-Fi 간 방화벽·VLAN 분리로 통신이 막힐 수 있습니다. 학교 내부망 이외의 **인터넷 공개 서비스에는 평문 HTTP/WS로 배포하지 마세요.**

### AWS Lightsail/EC2 또는 공개 서버에 배포

1. Ubuntu VM에 소스를 복사하고 위 Python 설치 과정을 수행합니다.
2. 게임 서버는 `127.0.0.1:8080`에만 바인딩합니다.
3. Caddy나 Nginx로 **HTTPS와 WSS**를 구성하고 공식 도메인을 연결합니다. Caddy 예시는 아래와 같습니다.

```caddyfile
# 도메인을 소유하고 서버 DNS와 방화벽을 설정한 뒤 사용
quiz.example.org {
    reverse_proxy 127.0.0.1:8080
}
```

4. 외부에서는 `https://quiz.example.org`로 접속합니다. 학생용 방 QR 주소도 HTTPS가 됩니다.
5. 서버 프로세스 자동 재시작(systemd 또는 Docker)과 방화벽을 설정합니다.

## Docker로 실행

```bash
export TEACHER_PASSWORD='여기에_8자_이상의_관리자_비밀번호'
docker compose up -d --build
```

기본 Compose 포트는 로컬호스트에만 노출하므로 공개 접속은 역방향 프록시에서 TLS를 종료해야 합니다. Docker를 인터넷에 직접 노출하지 않는 구성이 권장됩니다.

## 테스트

```bash
python -m unittest -v test_server
python benchmark.py
```

이 파일을 생성할 때 실제 로컬 aiohttp WebSocket 연결을 사용하여 다음을 확인했습니다.

- 학생 70명 입장 및 71번째 거부
- 70명 모두가 서로 다른 학생 69명의 이름·프로필을 받고, 위치 업데이트를 전원 수신
- 학생이 교사 권한 명령을 보내더라도 무시
- 서버가 마감 시 학생별 O/X 구역을 고정하고 정답·탈락·생존 계산
- 교사 비밀번호 검증, 게임 도중 늦게 들어온 학생 처리
- Wi-Fi 중단 후 임시 세션 키로 학생 ID와 게임 상태 복원
- 합성 부하: 70명 × 4Hz × 5초 = 1,400개 위치 갱신 입력, 각 학생에게 1,400개 변경 좌표 전달 확인

**중요한 성능 한계:** 부하 발생기와 서버는 같은 테스트 호스트에서 구동했습니다. 실제 학교 Wi-Fi, AWS 실서버, 브라우저의 Three.js 3D 70인 렌더링, 휴대폰 발열·FPS까지 검증했다는 의미는 아닙니다. 따라서 행사 전에 30→50→70명으로 실제 휴대폰 접속 시험을 진행해야 합니다.

## 운영 주의사항

- 교사 비밀번호는 **서버의 환경변수에만** 둡니다. HTML 안에 저장하지 않습니다.
- 방 코드는 3~6자리로 타인이 추측할 수 있으므로 입장 제어 수단으로 간주하지 마세요. 비공개 반 행사라면 추가 입장 승인 기능을 개발할 필요가 있습니다.
- 사용자 이름은 모든 참가자 화면에 표시됩니다. 실명 사용 여부는 학교 개인정보 처리 기준에 맞추세요.
- 외부 라이브러리 `three.js`, Pretendard, QR 코드 이미지를 CDN으로 불러옵니다. 외부 인터넷이 차단된 내부망에서는 CDN 파일의 별도 제공이 필요합니다.
- 서버는 정상적인 클라이언트의 위치만을 기본 검증합니다. 변조한 브라우저의 속도·순간이동까지 완전하게 방지하는 부정행위 방어형 서버는 아닙니다.
- 브라우저 탭이 35초 이상 끊기면 참가자 정보가 사라질 수 있습니다. 경기 도중 새로 입장하는 계정은 기존 규칙대로 해당 경기에서 관전자 처리됩니다.
- 교사 HTML에서 CSV로 읽어들인 문제은행은 기존 설계처럼 해당 브라우저의 로컬 저장소에 있습니다. 서버 재시작 시 현재 경기 방의 상태도 소멸합니다.
- 행사 전에 테스트와 별도로 교사 화면의 실제 FPS, 위치 반영 지연, 재접속 성공률, 정답 판정 정확도, 학교 정책 승인을 확인하세요.

## 파일

- `index.html`: 기존 원본에 WebSocket 동기화를 적용한 학생/교사 통합 화면
- `server.py`: 70명 정원, 전원 동기화, 교사 인증·서버 판정, 자동 재접속 지원
- `requirements.txt`: 서버 의존성
- `test_server.py`: 접속·권한·판정·재접속 통합 테스트
- `benchmark.py`: **한 호스트에서만 수행**하는 합성 트래픽 점검 도구
- `Dockerfile`, `compose.yaml`: 선택적 Docker 배포

기존 HTML의 원작자 표기 및 출처 링크는 그대로 유지했습니다.
